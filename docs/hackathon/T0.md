# T0 runbook - the minute the hackathon starts

Already done by the scaffold: this repo exists without git; the design and a reference demo are in `docs/concepts/`. Do not run `git init` until the rules are re-read.

1. Re-read the official rules and fill [rules.md](rules.md). Check them against [ADR 0001](../adr/0001-repo-posture.md); set it to accepted or amend it.
2. `node scripts/preflight.mjs` - every required tool ok. Create `.env` from `.env.example`.
3. `git init -b main`, then commit the scaffold as `chore: scaffold (prepared pre-event)`. The commit body says it holds docs and tooling only.
4. Create the remote and push (public if the rules require it).
5. WP1 day-1 task: probe the real Meta API with the key and fill [meta-api-facts.md](meta-api-facts.md). Every fact tagged measured / press / unverified. The plan's branches (Llama on the same key? SAM offered?) are decided from that file.
6. The Director commits the wire contract and compilable stubs (plan, "Work packages"); then WP1, WP2 and WP4 run in parallel and WP3 follows against the stubs.
7. Run `/spark resume blue-hour-onboarding` in this repo; the idea note is in `.spark/Spark/ideas/`.
8. Record the Muse transcripts (one per chore) only after WP1 lands; hero chore first.
